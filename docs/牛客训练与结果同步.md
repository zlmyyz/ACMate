# 牛客训练与官方结果同步

题目详情采用左右分栏：左侧为题目资料、完整题面与从原文提取的数据范围提示，右侧为黑色 CodeMirror 代码编辑器、自动加载的公开样例和正式提交操作。窄屏上下排列。

## 使用步骤

1. 导入牛客题目，进入题目详情。代码草稿按本站账号、题目、语言保存在当前浏览器。
2. 编辑器底部提供“自测输入 / 运行结果”面板与“自测运行”按钮。公开样例进入题目后自动读取，无需点击获取，输入和预期输出可编辑，可载入公开样例或自行填写输入，预期输出选填。未修改的公开样例由后端按样例编号读取；自定义用例将输入作为标准输入送入沙箱。自测不记正式 AC，也不写入提交热力图。
3. 点击编辑器底部“保存并跳转（牛客）”，将代码保存到浏览器并尝试复制到剪贴板后跳转，在牛客登录、粘贴代码、选择对应语言并自行完成提交。本站不代交，不读取牛客 Cookie、密码或隐藏测试数据。
4. 在“OJ 账号绑定”中填写牛客数字 UID，管理员核对本人身份后审核。Codeforces 与牛客可以同时绑定。
5. 返回本站后会尝试同步；也可点击“同步官方结果”。正式结果进入最近提交、热力图、首次通过及训练状态。

## 题目页单题同步范围

当前已验证牛客竞赛公开接口 `/acm-heavy/acm/contest/status-list`，仅支持来源是 `https://ac.nowcoder.com/acm/contest/{contestId}/{index}`、标识为 `NC{problemId}` 的题目。每次读取本人此题最近最多 60 条公开终态记录；间隔至少 20 秒。结果必须同时匹配已审核的个人 UID 和题目 ID，团队提交、未知状态和评测中记录不导入。

`/acm/problem/{id}` 或 `/practice/{uuid}` 来源暂不支持自动正式结果同步，因为尚未验证可无登录读取并校验归属的记录接口。界面明确显示限制，仍可编辑代码、读取样例和跳转官方。牛客提交详情页可能要求官方登录，本站不会绕过。

官方记录按 `(platform, remote_submission_id)` 去重。样例运行和本地预期输出不能写入正式统计。账号变更在写入前重新加锁核对；发现已有提交归属其他本站用户时拒绝迁移。

## 个人主页全历史同步与题面导入队列

个人主页可绑定牛客数字 UID、查看审核与任务状态，并切换全部平台、牛客或 Codeforces。每日提交、最近 10 条和通过统计一起切换。今日提交次数含错误提交；今日尝试题数按平台和题号去重；今日新增通过按最早官方 AC 的日期去重。热力图不包含本站样例运行。

经验证可匿名分页读取的来源是牛客竞赛个人主页 `/acm/contest/profile/{uid}/practice-coding`。同步任务逐页读取该页公开的编程终态记录，每页 50 条直到末页，不限制为最近 60 条。无法访问的私有记录、企业笔试记录和其他未在此公开列表展示的记录不在覆盖范围；未知结果和评测中记录不当作通过。历史补齐期间统计逐页更新，最终首 AC 日期可能向前修正。

- 账号须审核通过且启用同步。首次进入本人主页会发起同步；后台也会自动发现新审核账号，每小时补同步一次。手动重复触发复用正在运行的任务，已完成后再次发起至少间隔 60 秒。
- 提交记录以 `(NOWCODER, remote_submission_id)` 去重，归属来自已审核 UID；请求不能指定其他用户。官方时间按北京时间保存，补录历史不算成今天的提交。
- 先按 `(NOWCODER, NC题号)` 查询 `problem`。已存在的题目直接关联，不读取或覆盖题面，也不恢复停用题目。仅正式通过且尚无题面的题号进入导入队列；多个用户通过同题只排一个导入任务。
- 导入 worker 再次检查数据库后才访问官方公开题面；唯一约束处理并发手动创建或其他用户同时导入。题面完成后回填所有同题提交的站内链接与训练状态，题面失败不会阻塞提交统计。
- 队列持久化在 MySQL 的 `nowcoder_sync_job`、`nowcoder_problem_import_job`，有行锁认领、2 分钟租约和断点页码。网络失败间隔 30 秒重试，最多 5 次，超过后可在本人主页重试。后端重启后自动恢复未完成任务。
- 队列在现有 Spring 后端内消费，不增加新服务或中间件，已随 `启动前后端.bat` 的后端启动生效。可用 `acmate.nowcoder.queue.enabled=false` 暂停后台消费。
- 首次全历史同步和题面导入可能需要较长时间；主页展示页数、读取/新增记录数、题面待处理/完成/失败数，不阻塞页面请求。

接口：

- `GET /api/nowcoder/profile-sync`：本人队列状态。
- `POST /api/nowcoder/profile-sync`：本人发起/恢复同步，返回 202。
- `POST /api/nowcoder/profile-sync/retry-imports`：重新排队本人已通过题目的失败导入任务。
- `GET /api/users/{id}/oj-overview?platform=ALL|NOWCODER|CODEFORCES`：公开账号与统计，只展示已审核的 OJ 绑定。
- 原 activity、submissions/recent 接口接受同样的可选 platform 筛选。

公开主页的 GET 请求只读本地数据库，不向牛客发起抓取。队列接口必须登录，POST 必须 CSRF，其他用户无法触发你的同步。

## 样例执行环境

使用 MIT 开源项目 [criyle/go-judge](https://github.com/criyle/go-judge)，固定 v1.13.3。镜像配置位于 `deploy/judge`，支持 C++17、C17、Java17、Python3、C#/.NET 10、TypeScript 5.9、JavaScript/Node.js 24、Go 和 Rust。Java 使用 `public class Main`；所有语言采用标准输入/输出，仅使用镜像内的标准库，不在线安装第三方包。

日常运行项目上级目录的 `启动前后端.bat`，会自动启动 Docker Desktop（如有需要）、样例环境、Redis 和前后端。也可单独运行 `deploy/judge/start-judge.ps1`；首次构建镜像，后续复用；语言环境文件的指纹变化会自动重建，也可加 `-Rebuild` 强制重建。C# SDK 从微软官方源下载到 Git 忽略的 `.sdk-cache` 并按官方 SHA-512 校验，支持断点下载并串行准备，重复启动无需重新下载。启动脚本会等待 Linux Docker 引擎和样例 HTTP 服务就绪。首次生成的 `.judge-token` 仅保存在本机且已忽略 Git，不在聊天中展示。后端设置 `acmate.practice.enabled=true` 并重启后加载令牌；默认 URL 为 `http://127.0.0.1:5050`。

容器使用上游要求的 privileged 权限实现嵌套沙箱，只映射 `127.0.0.1:5050`，无网站源码或数据库目录挂载；容器上限 2 核、2 GiB、256 进程，沙箱并行度 1。保留默认 seccomp 与网络命名空间隔离，`-no-fallback` 确保 cgroup 无法启用时启动失败。

编辑器支持 Tab / Shift+Tab 缩进、Ctrl+/ 注释、Ctrl+F 查找、Ctrl+H 替换、撤销重做、Ctrl+' 或 Ctrl+Enter 自测运行公开样例、Ctrl+S 保存，以及 F11 放大和 Esc 还原。

单次运行限制 CPU 2 秒、墙钟 5 秒、内存 256 MiB、64 进程、标准输出 64 KiB、标准错误 16 KiB；编译限制 CPU 20 秒、墙钟 40 秒、内存 768 MiB。编译产物完成后删除。应用不在 Windows 主机直接启动编译器或执行用户程序。

## 接口

- `GET/POST/DELETE /api/nowcoder/account`：查看、申请绑定、解绑牛客 UID。
- 现有 OJ 管理审核接口审核牛客绑定，列表标识平台。
- `GET /api/nowcoder/problems/{id}`：官方链接和同步支持状态。
- `GET /api/nowcoder/problems/{id}/submissions`：本人此题最近 10 条已同步记录。
- `POST /api/nowcoder/problems/{id}/sync`：同步公开官方结果。
- `GET /api/practice/status`：样例环境可用状态。
- `GET /api/practice/problems/{id}/samples`：读取公开样例。
- `POST /api/practice/run`：运行指定题目的公开样例或自定义输入。共同字段为 problemId、language、sourceCode；PUBLIC_SAMPLE 模式传 sampleIndex，CUSTOM 模式传 input（可为空字符串，最多 65536 字符）。

接口均需本站登录，写操作另需 CSRF。普通用户不能直接提交“官方结果”或 AC 状态。



## 代码补全账号设置

编辑器工具栏提供“代码补全”开关，关闭时立即关闭提示列表并停用自动和手动补全；开启后恢复当前语言的关键字与文档词汇建议。保留原有语言模式提供的建议，不依赖远程 LSP 或额外服务。

设置存储在 `user_editor_setting`，本机按账号缓存，登录时从后端读取，可在不同设备上沿用。快速连续切换按顺序保存最后的选择；账号切换后不应用旧账号请求结果。设置同步失败时保留本机选择并提供重试按钮。账号合并时优先保留主账号设置，否则继承源账号设置。

`GET/PUT /api/users/me/editor-settings` 需登录，PUT 需 CSRF；请求包含 autocomplete 和用于防止账号切换竞态的 accountId，后端必须与当前登录账号一致才保存。
