# 统一登录身份表

从 V21 起，`user_login_identity` 是邮箱、GitHub 登录及绑定关系的唯一查询来源。`app_user` 保存主账号资料、密码、权限和状态。两种登录方式绑定后共享同一个 `user_id`。

| 字段 | 含义 |
| --- | --- |
| id | 身份记录 ID |
| user_id | 主账号 ID，外键关联 app_user |
| provider | EMAIL 或 GITHUB |
| identifier | 规范化邮箱，或 GitHub 永久数字 ID 的字符串 |
| login_name | GitHub 当前登录名 |
| display_name | GitHub 当前显示名称 |
| create_time / update_time | 身份记录创建、更新时间 |

数据库唯一约束：

- `(provider, identifier)`：同一登录身份只能属于一个主账号。
- `(user_id, provider)`：每个主账号最多绑定一个邮箱、一个 GitHub。

## 迁移和兼容

V21 自动导入已有邮箱及 GitHub 绑定。已合并的停用账号不导入邮箱身份，原有主账号 ID、权限及业务数据不变。

`app_user.email` 暂保留为资料接口的联系邮箱兼容字段；注册及换绑在同一事务内同步更新身份表与该字段。邮箱登录、找回密码、邮箱占用检查以身份表为准，不根据联系字段创建第二个身份。

原 `user_github` 表改名为 `user_github_legacy`，只保留迁移前的数据用于核对。原名称建立只读兼容视图；运行时代码直接使用新身份表。旧表不再接收绑定更新，不能用它判断当前绑定状态。

注册/首次登录时才创建主账号；绑定已有账号仅新增或迁移身份记录。两个已独立注册的账号仍须完成双方身份验证并明确确认合并，不能仅凭 GitHub 返回的邮箱自动合并。

换绑邮箱更新 EMAIL 身份，旧邮箱不再用于登录；解绑 GitHub 只删除 GITHUB 身份，要求仍有可用邮箱登录。合并操作在事务内迁移身份和业务数据、停用旧账号并撤销旧会话，保留合并日志。

未存储 GitHub access token、邮箱验证码或明文密码。邮箱验证码继续仅保存在 Redis。
