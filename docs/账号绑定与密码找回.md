# 账号绑定与密码找回

注册页面必须填写邮箱并验证六位验证码。邮箱验证码登录仍支持未注册时自动创建账号。

## 页面

- `/register`：注册，邮箱和邮箱验证码必填。
- `/settings/profile`：绑定邮箱、换绑邮箱、绑定 GitHub。
- `/account-link`：GitHub 已验证邮箱对应已有本站账号时，询问是否绑定；验证邮箱后才合并。
- `/forgot-password`：通过已绑定邮箱的验证码设置 8–64 位新密码。
- `/users/:id`：已绑定 GitHub 的右侧显示 GitHub 名称与用户名。

## 绑定规则

邮箱换绑需要原邮箱和新邮箱验证码。原邮箱无法使用时需要联系管理员处理。

GitHub 绑定通过 OAuth state 和 PKCE 校验，GitHub 身份在服务器端获取，不接受前端传入的 GitHub ID。授权后先展示待绑定信息，用户确认才更新数据库。

发现邮箱与 GitHub 各有一个独立账号时，需要确认合并。保留邮箱账号的 ID、用户名、密码及个人资料，转移另一账号的 GitHub 绑定、题目、训练计划、训练进度、讨论、通知、OJ 数据等；重复点赞和首 AC 记录去重。合并在数据库事务中进行，失败则全部回滚。原账号保留为停用的历史记录，`merged_into_user_id` 指向保留账号，并写入 `account_merge_log`。

两个账号已经绑定不同邮箱、不同 GitHub 或同一平台的不同 OJ 账号时，会阻止合并并提示处理冲突，防止覆盖身份信息。合并后原有会话失效，当前浏览器重新登录保留账号。

密码重置不会自动注册账号。成功后旧密码失效、原有登录会话失效，当前浏览器退出登录。

个人资料中的“修改密码”需要输入原密码、新密码和确认新密码。后端验证原密码及两次新密码一致后保存密码散列，并使现有会话失效，返回登录页重新登录。忘记原密码时，点击旁边的“忘记密码？”通过邮箱验证码重设。

GitHub 支持在个人资料中通过确认弹窗解绑。解绑前必须绑定邮箱且邮箱登录服务可用；解绑只移除 GitHub 登录关联，账号资料和业务数据保留，其他登录会话失效，当前浏览器继续登录。解绑同时清除当前会话未完成的 GitHub 授权与绑定凭证。

## 接口

修改接口使用现有 CSRF token。通过 `GET /api/auth/csrf` 获取，放入对应请求头。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/auth/register/code` | 发送注册验证码 |
| POST | `/api/auth/register` | 注册，新增必填 `emailCode` |
| POST | `/api/auth/password/code` | 发送重置密码验证码 |
| POST | `/api/auth/password/reset` | `email`、`code`、`password` |
| POST | `/api/users/me/password` | 登录后传 `currentPassword`、`newPassword`、`confirmPassword` 修改密码 |
| GET | `/api/users/me/bindings` | 当前邮箱、GitHub 绑定状态、GitHub 名称 |
| POST | `/api/users/me/email/code` | 发送新邮箱验证码；`current: true` 则发到服务端记录的原邮箱 |
| POST | `/api/users/me/email/prepare` | `email`、`code`、`currentCode`，校验后返回合并提示信息 |
| POST | `/api/users/me/email/confirm` | `confirm: true`，完成已验证邮箱的绑定 |
| POST | `/api/users/me/github/authorize` | 发起绑定授权 |
| GET | `/api/users/me/github/pending` | 读取本次待绑定 GitHub 信息 |
| POST | `/api/users/me/github/confirm` | `confirm: true`，完成绑定或合并 |
| POST | `/api/users/me/github/unlink` | `confirm: true`，解绑当前用户的 GitHub，返回刷新后的登录信息 |
| POST | `/api/users/me/bindings/cancel` | 丢弃当前绑定凭证 |
| GET | `/api/auth/github/link` | GitHub 登录时发现已有邮箱账号的脱敏提示 |
| POST | `/api/auth/github/link/code` | 向服务端确定的已有邮箱发送绑定验证码 |
| POST | `/api/auth/github/link/confirm` | `code`、`confirm: true`，确认合并并登录 |
| POST | `/api/auth/github/link/skip` | 不绑定，继续 GitHub 登录 |

## 验证码存储

Redis 哈希保存密码散列后的验证码与尝试次数，五分钟过期，最多尝试五次，成功后通过 Lua 原子删除，不能再次使用。用途分别为 `LOGIN`、`REGISTER`、`RESET`、`BIND:<用户ID>`、`CURRENT:<用户ID>`、`LINK:<GitHubID>`，不同用途不能混用。

登录验证码沿用 `acmate:login:email-code:<邮箱SHA256>`，其余使用 `acmate:login:email-code:<用途>:<邮箱SHA256>`。发信频率限制沿用邮箱每分钟一次、IP 每小时十次。Redis 写入使用兼容 Redis 3.2 的 `HMSET`。

现有 GitHub 账号的名称会在下次 GitHub 登录时同步；也可在个人资料中点击“同步 GitHub 名称”重新授权。
