# ACMate 产品需求文档（PRD）

> 文档版本：v1.4  
> 产品阶段：功能需求冻结前  
> 产品类型：校内程序设计竞赛社团内部训练与题目交流平台  
> 前端技术方向：Vue 3（原型与视觉方案后续由 Stitch 产出）  
> 本文档重点：功能模块、业务规则、权限、页面信息结构、状态与验收标准；暂不约束具体视觉风格。

---

## 1. 产品背景

程序设计竞赛社团的日常训练通常分散在多个平台中：

- 题目来源分散在 Codeforces、牛客、自建题目和其他 OJ；
- 训练计划依赖群聊、在线表格或临时文档；
- 题解和讨论难以长期沉淀；
- 社员的刷题数量、完成情况和活跃度缺乏统一统计；
- 社长或管理员难以快速了解成员训练进度；
- 新成员缺少清晰的训练入口和题目路径。

ACMate 用于把社团内部的题目、训练、讨论和统计集中到一个平台中。产品不替代在线判题系统，而是作为社团训练组织层和内容沉淀层。

---

## 2. 产品目标

### 2.1 核心目标

1. 建立统一的社团题库，支持社员共同创建和维护题目。
2. 让成员可以浏览、搜索、创建、编辑、停用和恢复自己拥有的题目。
3. 让管理员在普通用户能力之上管理全站资源。
4. 支持训练计划的创建、编排和成员完成情况统计。
5. 支持围绕题目或竞赛经验进行发帖、评论和点赞。
6. 接入可用的 OJ 数据，统计成员刷题量并生成排行榜。
7. 为社长和管理员提供社团训练概览和异常处理入口。

### 2.2 非目标

第一版不以以下能力为目标：

- 自建在线判题系统；
- 在线运行代码和评测代码；
- 面向公众的大型社区；
- 商业化、付费会员或广告系统；
- 复杂的组织架构和多租户；
- 即时聊天；
- 物理删除题目；
- 完整的内容审核工作流；
- 与所有 OJ 平台同时实现稳定同步。

## 3. 目标用户与角色

系统只保留两类权限角色。

### 3.1 普通用户

普通用户即社团成员，能够：

- 注册、登录和退出；
- 浏览公开题目；
- 查看其他成员的公开主页和公开题目；
- 创建题目；
- 修改、停用、恢复自己创建的题目；
- 查看自己的正常和停用题目；
- 参与训练计划；
- 发布帖子、评论和点赞；
- 绑定支持的 OJ 账号；
- 查看个人刷题统计和排行榜。

### 3.2 管理员

管理员首先是普通用户，拥有普通用户的全部能力，并额外能够：

- 查看所有用户的正常和停用题目；
- 修改、停用和恢复任意题目；
- 管理违规帖子和评论；
- 查看成员训练与同步状态；
- 管理训练计划和平台运营数据；
- 处理异常同步任务；
- 后续执行用户状态管理。

### 3.3 权限原则

管理员权限是普通用户权限的超集，不设计一套与普通用户割裂的后台业务。

资源管理权限统一遵循：

```text
允许管理资源
= 当前用户是资源创建者
  或
  当前用户是管理员
```

前端可以隐藏无权限按钮，但最终权限必须由后端校验。

## 4. 核心业务对象

### 4.1 用户

包含：

- 用户 ID；
- 用户名；
- 昵称；
- 邮箱；
- 头像；
- 管理员标识；
- 用户状态；
- 创建时间和更新时间。

### 4.2 题目

包含：

- 平台；
- 外部题目标识；
- 标题；
- 来源链接；
- 难度；
- 标签；
- Markdown 正文；
- 创建者；
- 状态；
- 创建时间和更新时间。

题目状态：

- `ACTIVE`：正常，可出现在公共题库；
- `INACTIVE`：已停用，不出现在公共题库。

停用不是删除，题目记录和平台题目标识继续保留。

### 4.3 训练计划

训练计划用于组织一组有顺序或主题的题目，包含：

- 计划名称；
- 计划说明；
- 创建者；
- 开始时间；
- 结束时间；
- 计划状态；
- 题目列表；
- 题目顺序；
- 参与成员；
- 成员完成情况。

### 4.4 用户做题状态

用于记录某个成员与某道题之间的训练状态，例如：

- 未开始；
- 尝试中；
- 已通过；
- 已放弃或暂缓；
- 最近更新时间。

该状态既可以来自用户手动记录，也可以在 OJ 同步成功后更新。

### 4.5 帖子与评论

帖子用于题解、讨论、训练总结和竞赛经验分享。

包含：

- 标题；
- 正文；
- 作者；
- 关联题目或训练计划（可选）；
- 状态；
- 点赞数；
- 评论数；
- 创建时间和更新时间。

### 4.6 OJ 账号与提交记录

用户可绑定外部 OJ 账号。系统保存：

- 平台；
- 外部账号标识；
- 绑定状态；
- 最近同步时间；
- 同步错误；
- 外部提交记录；
- 去重后的通过题目记录。

### 4.7 排行榜

排行榜基于可信的做题数据生成，至少支持：

- 总通过题数；
- 最近 7 天通过题数；
- 最近 30 天通过题数；
- 当前训练计划完成数；
- 最后活跃时间。

## 6. 功能模块需求

# 6.1 认证与会话

## 6.1.1 注册

用户填写：

- 用户名；
- 昵称；
- 邮箱，可选；
- 密码；
- 确认密码，仅前端使用。

规则：

- 用户名全局唯一；
- 昵称全局唯一，且大小写不敏感；
- 邮箱非空时全局唯一；
- 密码由后端使用 BCrypt 保存；
- 客户端不能指定管理员身份；
- 注册成功后跳转登录页；
- 注册成功不自动视为已登录。

主要异常：

- 字段格式错误；
- 用户名已存在；
- 邮箱已存在；
- 系统异常。

## 6.1.2 登录

用户使用用户名和密码登录。

要求：

- 使用 Session Cookie 保持登录；
- 不使用 JWT；
- 登录成功返回当前用户基本信息；
- 登录失败不暴露“用户名是否存在”；
- 禁用用户不能登录；
- 刷新页面后应能恢复登录状态。

## 6.1.3 当前用户

应用初始化时查询当前会话用户。

结果：

- 已登录：恢复用户信息和权限；
- 未登录：进入游客状态；
- 会话失效：跳转登录页。

## 6.1.4 退出

退出操作需要有效 CSRF Token。

退出后：

- 服务端 Session 失效；
- 前端清空当前用户状态；
- 受保护页面重新访问时跳转登录页。

# 6.2 首页

首页用于社团训练概览和常用入口。

第一版模块：

- 当前用户欢迎信息；
- 浏览题库入口；
- 创建题目入口；
- 我的题目入口；
- 训练计划入口；
- 平台说明；
- 后续功能规划。

后端具备统计接口后增加：

- 我的总通过题数；
- 本周通过题数；
- 当前训练计划进度；
- 最近发布题目；
- 最近讨论；
- 社团排行榜摘要。

禁止在后端没有真实数据时展示伪造统计值。

---

# 6.3 公共题库

## 6.3.1 题目列表

所有已登录用户均可访问。

默认只展示 `ACTIVE` 题目。

筛选条件：

- 关键词；
- 平台；
- 难度；
- 创建者；
- 页码；
- 每页数量。

关键词匹配：

- 题目标题；
- 外部题目标识。

排序：

1. 创建时间倒序；
2. ID 倒序。

列表字段：

- 标题；
- 平台；
- 外部题目标识；
- 难度；
- 标签；
- 创建者；
- 创建时间。

公共列表不返回停用状态，因为结果全部为正常题目。

## 6.3.2 查看某用户的公开题目

用户进入他人主页后，可以查看该用户创建的 `ACTIVE` 题目。

普通用户不能通过创建者筛选查看对方的 `INACTIVE` 题目。

---

# 6.4 题目详情

正常题目：

- 所有已登录用户可查看。

停用题目：

- 创建者可查看；
- 管理员可查看；
- 其他普通用户返回“题目不存在”。

详情内容：

- 标题；
- 平台；
- 外部题目标识；
- 来源链接；
- 难度；
- 标签；
- Markdown 正文；
- 创建者；
- 状态；
- 创建和更新时间；
- 当前用户可执行的操作。

停用题目详情需明确提示：

> 该题目当前已停用，不会出现在公共题库中。

---

# 6.5 创建题目

所有已登录用户都能创建题目。

输入字段：

- 平台；
- 外部题目标识；
- 标题；
- 来源链接；
- 难度；
- 标签；
- Markdown 正文。

业务规则：

- 非自定义平台必须提供外部题目标识；
- 自定义平台可不提供；
- 标签按英文逗号拆分、去空、去重并保持顺序；
- 创建者 ID必须来自当前认证用户；
- 新题状态由服务端固定为 `ACTIVE`；
- 客户端不能指定创建者和状态；
- 同一平台和外部题目标识不能重复；
- 停用题目仍占用原平台题目标识。

创建成功后进入题目详情。

---

# 6.6 编辑题目

可编辑者：

- 题目创建者；
- 管理员。

其他普通用户无权编辑。

允许修改：

- 平台；
- 外部题目标识；
- 标题；
- 来源链接；
- 难度；
- 标签；
- Markdown 正文。

禁止修改：

- 题目 ID；
- 创建者；
- 状态；
- 创建时间。

规则：

- 正常题目可以编辑；
- 停用题目也可以编辑；
- 编辑停用题目不会自动恢复；
- 可空字段允许清空；
- 更新成功后显示数据库中的最新结果；
- 外部题目标识查重时排除当前题目。

---

# 6.7 我的题目

所有已登录用户可查看自己的题目管理页。

状态筛选：

- `ALL`：全部；
- `ACTIVE`：正常；
- `INACTIVE`：已停用。

其他筛选：

- 关键词；
- 平台；
- 难度；
- 分页。

查询用户 ID必须来自当前会话，客户端不能传入另一个用户 ID。

列表字段：

- 标题；
- 平台；
- 难度；
- 标签；
- 状态；
- 创建时间；
- 更新时间；
- 查看；
- 编辑；
- 停用或恢复。

空状态：

- 全部为空：提示创建第一道题目；
- 已停用为空：提示暂无已停用题目；
- 筛选无结果：提供清空筛选入口。

# 6.8 停用与恢复题目

## 6.8.1 停用

可操作者：

- 创建者；
- 管理员。

行为：

- `ACTIVE → INACTIVE`；
- 已经是 `INACTIVE` 时重复停用仍返回成功；
- 不进行物理删除；
- 停用后从公共题库消失；
- 创建者和管理员仍可查看、编辑和恢复；
- 外部题目标识继续被占用。

## 6.8.2 恢复

可操作者：

- 创建者；
- 管理员。

行为：

- `INACTIVE → ACTIVE`；
- 已经是 `ACTIVE` 时重复恢复仍返回成功；
- 恢复后重新出现在公共题库。

## 6.8.3 物理删除

系统不提供物理删除。

原因：

- 社团规模下存储压力有限；
- 题目未来会关联训练计划、做题状态、提交和帖子；
- 保留数据有利于审计和历史统计；
- 避免关联记录失效。

# 6.9 管理员全部题库

管理员可以在普通题库能力之上查看全站题目。

筛选条件：

- 状态：全部、正常、已停用；
- 创建者；
- 平台；
- 难度；
- 关键词；
- 分页。

列表字段：

- 题目基本信息；
- 状态；
- 创建者 ID；
- 创建者用户名；
- 创建者昵称；
- 创建时间；
- 更新时间；
- 管理操作。

管理员可以：

- 查看任意停用题目；
- 编辑任意题目；
- 停用任意正常题目；
- 恢复任意停用题目。

管理员列表查询创建者信息时应避免逐条查询导致 N+1 问题。

# 6.10 用户主页

用户主页用于展示成员的公开资料与训练贡献。

第一版展示字段：

- 用户名；
- 昵称；
- 头像；
- 注册时间；
- 个人简介；
- Codeforces 账号（是否公开由用户设置）；
- OJ 验证刷题统计；
- 创建的公开题目；
- 参与的公开训练计划。

明确不展示：

- 邮箱；
- 学号；
- 年级；
- 专业；
- 私有训练计划；
- 停用题目；
- 详细私有训练进度。

资料规则：

- 用户名不可修改；
- 昵称可以修改，但须全局唯一；
- 第一版支持头像上传；
- 管理员可以修改违规用户的昵称或头像；
- 邮箱仅本人和管理员可见，不出现在公开主页；
- OJ 账号公开状态由用户自行设置。

训练信息：

- 其他用户可以查看该成员创建的 `ACTIVE` 题目；
- 可以查看该成员参与的公开训练计划；
- 公开计划中的详细进度遵循训练计划的成员可见性规则；
- 本人管理停用题目时进入“我的题目”；
- 管理员查看该用户全部题目时进入管理员查询视图。

# 6.11 训练计划

## 6.11.1 训练计划类型

训练计划分为：

- `PERSONAL`：个人计划；
- `PUBLIC`：公开计划。

### 个人计划

- 所有已登录用户均可创建；
- 仅创建者本人使用；
- 不出现在公共训练计划列表；
- 其他普通用户不能加入或查看；
- 创建者可以管理计划内容；
- 管理员可以基于全站权限查看和管理。

### 公开计划

- 只有管理员可以创建；
- 对所有已登录用户可见；
- 用户可以自由加入，不需要审批；
- 用户不能主动退出；
- 管理员或计划创建者可以移除参与者；
- 被移除成员的历史完成数据继续保留；
- 第一版不支持管理员强制把用户加入计划；
- 第一版不限制参与人数。

训练计划创建者 ID 必须来自当前认证用户，客户端不能指定。

计划类型创建后是否允许切换，仍需最终确认。第一版建议模式固定，避免参与关系和权限混乱。

## 6.11.2 时间与状态

开始时间和结束时间均可选，支持长期题单。

时间状态由系统自动计算：

- `NOT_STARTED`：尚未开始；
- `ONGOING`：进行中；
- `ENDED`：已结束。

停用状态单独控制，不与时间状态混合。

公开计划被停用后：

- 已有参与者仍可查看计划详情；
- 可以查看题目列表；
- 可以查看自己的历史进度；
- 不允许继续修改题目完成状态；
- 不再接受新成员加入；
- 创建者或管理员仍可编辑计划内容；
- 编辑不会自动恢复计划。

结束后的计划：

- 参与者仍可查看题目和赛时排名快照；
- 可以继续补做并更新个人做题状态；
- 截止时统计结果保持冻结，不因赛后补做改变；
- 是否允许新用户在结束后加入，仍需最终确认。

## 6.11.3 训练计划内容

计划包含：

- 名称；
- 说明；
- 类型；
- 创建者；
- 开始时间；
- 结束时间；
- 时间状态；
- 停用状态；
- 题目列表；
- 题目顺序；
- 参与成员；
- 当前用户完成进度；
- 赛时统计快照；
- 创建时间和更新时间。

同一道题在同一计划中不允许重复添加。

题目被停用后：

- 仍保留在训练计划中；
- 显示“题目已停用”；
- 不自动从计划移除。

## 6.11.4 权限

个人计划：

- 创建者可修改、停用和恢复；
- 管理员可以管理全部个人计划。

公开计划：

- 只有管理员可创建；
- 创建者本身也是管理员；
- 创建者或其他管理员可以修改、停用、恢复；
- 可以移除参与者；
- 普通参与者不能修改计划内容。

成员进度：

- 公开计划参与者之间可以互相查看进度；
- 创建者和管理员可以查看全部成员进度；
- 普通用户不能查看自己未参与计划的详细成员进度。

## 6.11.5 公开计划加入

- 所有已登录用户均可自由加入正在开放的公开计划；
- 加入后创建参与关系并记录加入时间；
- 用户不允许主动退出；
- 管理员移除用户时保留历史进度；
- 停用计划不接受新成员；
- 第一版不支持人数上限；
- 第一版不支持邀请制或强制加入。

## 6.11.6 赛时与赛后数据

赛时统计至少记录：

- 参与人数；
- 各成员已通过题目数；
- 完成顺序；
- 截止时排名；
- 截止时完成时间。

计划结束后：

- 保留并展示赛时排名快照；
- 赛后补做不修改赛时排名；
- 赛后完成状态可以继续更新；
- 页面需区分“赛时成绩”和“当前补做进度”。

第一版不做个人计划一键复制为公开计划，后续可增加”复制计划”。

## 6.11.7 训练计划题目管理

训练计划创建时可以不包含题目，后续由创建者编辑添加。

### 创建计划时的题目选择

- 创建计划时可以多选题目加入计划；
- 题目按选择顺序自动分配 `sortOrder`；
- 同一计划中不允许重复添加同一道题目；
- 只允许选择状态为 `ACTIVE` 的题目；
- 停用题目不出现在可选列表中。

### 编辑计划时的题目管理

- 创建者可以随时添加题目；
- 创建者可以随时移除题目；
- 创建者可以调整题目顺序（重排）；
- 已停用的题目仍保留在计划中，展示时标注”已停用”；
- 编辑计划标题或说明不会触发题目变更通知。

### 通知

题目变更（添加、移除、重排）后发送 `TRAINING_PROBLEMS_CHANGED` 通知给所有计划成员。

### 事务

题目批量操作在同一事务中执行，任一步骤失败则整体回滚。

# 6.12 做题状态

做题状态只保留三种：

- `NOT_STARTED`：未做；
- `CHALLENGING`：挑战中，尚未通过；
- `ACCEPTED`：已通过。

规则：

- 用户可以手动设置 `NOT_STARTED` 和 `CHALLENGING`；
- 用户不能手动设置 `ACCEPTED`；
- `ACCEPTED` 只能由可信 OJ 同步记录确认；
- 已由 OJ 确认的 `ACCEPTED` 不能手动降级；
- 相同用户对同一道题多次通过，正式通过题数只计算一次；
- 全局通过状态在不同训练计划之间共用；
- 公开计划仍单独记录用户加入计划后的完成时间，用于计划统计；
- 第一版支持一条简短备注，不做复杂笔记或复习系统。

自定义题目当前没有可信 OJ 通过记录，因此不能手动计入正式刷题排行榜。其完成情况可以作为训练计划内部进度单独展示。

# 6.13 讨论区

## 6.13.1 帖子类型

帖子类型固定为：

- 题解；
- 问题求助；
- 竞赛总结；
- 训练经验；
- 公告；
- 其他。

普通用户不能发布公告，公告仅管理员可发布。

## 6.13.2 发布帖子

所有已登录用户可以发布非公告帖子。

字段：

- 标题；
- Markdown 正文；
- 类型；
- 关联题目；
- 关联训练计划（可选）。

规则：

- 题解类型必须关联题目；
- 其他类型关联题目可选；
- Markdown 完全禁止原始 HTML；
- 所有 HTML 标签均不得作为可执行或可渲染 HTML 处理；
- 前端渲染 Markdown 时必须关闭原始 HTML 能力；
- 后端保存前不依赖前端过滤作为安全边界；
- 作者可以编辑和主动停用自己的帖子；
- 管理员可以管理全部帖子。

## 6.13.3 帖子停用与恢复

使用逻辑停用，不物理删除。

作者主动停用：

- 作者和管理员仍可查看；
- 作者可以继续编辑；
- 作者可以自行恢复。

管理员强制停用：

- 作者仍可以查看和编辑；
- 作者不能自行恢复；
- 只能由管理员恢复；
- 管理员停用时必须填写原因。

为支持上述差异，数据库需要区分：

- 作者主动停用；
- 管理员强制停用。

## 6.13.4 评论与回复

第一版支持：

- 一级评论；
- 对一级评论进行一层回复；
- 不支持无限嵌套。

评论同样采用逻辑停用。

权限：

- 评论作者可以停用自己的评论；
- 管理员可以管理全部评论；
- 被管理员强制停用的评论不能由作者自行恢复。

## 6.13.5 点赞

第一版只支持帖子点赞，不支持评论点赞。

要求：

- 同一用户对同一帖子最多一个有效点赞；
- 支持取消点赞；
- 点赞和取消操作幂等；
- 列表与详情展示点赞数；
- 后续可用于热门排序。

# 6.14 OJ 账号绑定与同步

## 6.14.1 第一版平台

第一版只接入 Codeforces，不做牛客自动同步。

## 6.14.2 账号绑定

规则：

- 每个 ACMate 用户最多绑定一个 Codeforces 账号；
- 同一个 Codeforces 账号不能被多个 ACMate 用户绑定；
- 用户可以设置该账号在个人主页中公开或隐藏；
- 管理员可以查看用户绑定账号，用于审核与故障处理。

## 6.14.3 账号归属验证

第一版使用管理员审核：

1. 用户提交 Codeforces handle；
2. 系统读取公开信息并检查账号存在；
3. 绑定状态进入 `PENDING`；
4. 管理员审核后变为 `VERIFIED`；
5. 未审核或审核失败的账号不进入正式排行榜统计。

## 6.14.4 修改绑定账号

用户更换 Codeforces 账号后：

- 旧账号历史提交记录保留；
- 旧账号数据不再计入当前统计；
- 新账号重新进入审核流程；
- 统计页面需要标识数据来源账号和有效期。

## 6.14.5 同步方式

第一版支持：

- 用户手动同步；
- 每日定时同步。

暂不实现：

- 登录即同步；
- 牛客同步。

手动同步冷却时间仍需最终确认。

同步状态：

- `PENDING`：等待；
- `RUNNING`：进行中；
- `SUCCESS`：成功；
- `FAILED`：失败。

同步失败时：

- 用户看到可理解的错误原因；
- 不展示内部异常、第三方请求详情、堆栈或敏感参数；
- 管理员可以查看更详细的任务信息并重试。

## 6.14.6 提交去重

- 同一外部提交不能重复入库；
- 同一用户多次通过同一道题，提交记录可保留多条；
- 正式排行榜只计算唯一通过题目；
- 不同平台和外部题号分别统计；
- 第一版不做跨平台题目合并。

# 6.15 排行榜

正式刷题排行榜只统计经过 OJ 验证的通过数据。

不计入正式刷题榜：

- 用户手动状态；
- 自定义题目手动完成；
- 未审核通过的 OJ 账号数据。

第一版排行榜：

- 总榜；
- 最近 7 天；
- 最近 30 天。

不单独提供“本周榜”，避免与滚动 7 天口径混淆。

排序规则：

1. 唯一通过题数降序；
2. 最后通过时间或达成该题数时间作为次级规则；
3. 用户 ID作为稳定排序兜底。

展示：

- 排名；
- 用户昵称；
- 通过题数；
- 时间范围；
- 当前用户即使不在当前页，也显示自己的排名。

隐私规则：

- 社团成员默认参与排行榜；
- 用户不能主动隐藏或退出排行榜；
- 公开展示以昵称为主；
- 用户名作为次级信息。

管理员不能直接修改排名，只能处理错误账号、错误提交或重新同步数据。

不同平台相同题目按平台和外部题号分别计算，第一版不做跨平台合并。

# 6.16 管理功能

## 6.16.1 题目管理

管理员可以查看、筛选、编辑、停用和恢复任意题目。

管理员强制停用他人题目时：

- 必须填写原因；
- 创建者仍可查看和编辑；
- 创建者不能自行恢复；
- 只能由管理员恢复。

因此题目需要区分创建者主动停用和管理员强制停用。

## 6.16.2 内容管理

管理员可以：

- 查看帖子和评论；
- 停用违规内容；
- 填写停用原因；
- 恢复被管理员停用的内容；
- 查看作者和关联资源。

## 6.16.3 用户管理

管理员可以：

- 查看用户；
- 禁用和启用用户；
- 修改违规用户的昵称或头像；
- 提升普通用户为管理员；
- 取消其他管理员权限；
- 查看用户题目、训练和同步概览。

规则：

- 提升管理员必须二次确认；
- 管理员不能取消自己的管理员身份；
- 系统必须至少保留一个管理员；
- 第一版不提供用户自行注销。

用户被禁用后：

- 不能登录；
- 公开题目、帖子等内容继续保留；
- 页面显示“账号已停用”；
- 排行榜历史数据保留；
- 不参与当前排行榜。

## 6.16.4 管理员操作日志

必须记录：

- 操作者用户 ID；
- 操作类型；
- 资源类型；
- 资源 ID；
- 操作原因；
- 操作前状态；
- 操作后状态；
- 操作时间。

高风险操作必须二次确认。

## 6.16.5 同步任务管理

管理员可以查看任务、重试失败任务、审核 Codeforces 账号，以及处理错误账号和错误提交记录。

## 6.16.6 数据导出

管理员需要导出：

- 训练计划成员进度；
- 排行榜；
- 成员刷题数据；
- 题目列表；
- 同步失败记录。

优先导出为 Excel 或 CSV，具体格式在实现前确定。

# 6.17 通知

第一版只做站内未读通知列表，不做邮件/短信/WebSocket 推送。

通知场景（已实现 11 种）：

1. 帖子被评论（POST_COMMENTED）
2. 评论被回复（COMMENT_REPLIED）
3. 管理员停用帖子（POST_ADMIN_DEACTIVATED）
4. 管理员停用评论（COMMENT_ADMIN_DEACTIVATED）
5. 管理员恢复帖子（POST_RESTORED）
6. 管理员恢复评论（COMMENT_RESTORED）
7. 被移出训练计划（TRAINING_MEMBER_REMOVED）
8. 管理员停用训练计划（TRAINING_ADMIN_DEACTIVATED）
9. 管理员恢复训练计划（TRAINING_RESTORED）
10. 训练计划时间变更（TRAINING_SCHEDULE_CHANGED）
11. 训练计划题目变更（TRAINING_PROBLEMS_CHANGED）

未实现场景（后续版本）：

- 训练计划即将开始或结束；
- OJ 账号审核结果；
- OJ 同步失败。

要求：

- 显示未读数量；
- 支持单条标记已读；
- 支持全部标记已读；
- 点击通知跳转到相关资源；
- 30 秒轮询未读计数，页面不可见时自动暂停；
- 不做每日或每周训练总结。

架构：

- MySQL + `@TransactionalEventListener(AFTER_COMMIT)` best-effort 投递；
- 不含 WebSocket、邮件/短信、Outbox/MQ；
- 自操作不产生通知（actorUserId == recipientUserId 跳过）；
- 持久化失败只记日志，不阻塞业务。

## 8. 关键业务流程

### 8.1 创建题目

```text
登录
→ 打开创建题目
→ 填写字段
→ 前端校验
→ 获取 CSRF Token
→ 提交创建
→ 后端设置创建者和 ACTIVE
→ 返回详情
→ 跳转题目详情
```

### 8.2 停用并继续编辑

```text
创建者进入题目详情
→ 点击停用
→ 确认
→ 状态变为 INACTIVE
→ 从公共题库消失
→ 仍能在“我的题目-已停用”查看
→ 继续编辑
→ 保存后状态仍为 INACTIVE
```

### 8.3 恢复题目

```text
进入“我的题目-已停用”
→ 点击恢复
→ 状态变为 ACTIVE
→ 重新出现在公共题库
```

### 8.4 管理员处理他人题目

```text
管理员进入全部题库
→ 筛选创建者或停用状态
→ 打开题目
→ 编辑、停用或恢复
```

### 8.5 OJ 同步

```text
绑定账号
→ 触发同步
→ 创建同步任务
→ 获取外部提交
→ 去重入库
→ 更新用户通过记录
→ 更新排行榜
```

## 9. 状态、空状态和异常

### 9.1 页面加载状态

- 应用启动时显示初始化状态，等待 Session 恢复；
- 列表首次加载使用骨架或加载占位；
- 筛选时只刷新内容区域；
- 表单提交期间禁止重复点击；
- 操作失败保留用户输入。

### 9.2 空状态

公共题库无结果：

> 没有找到符合当前条件的题目。

我的题目为空：

> 你还没有创建题目。

已停用为空：

> 暂无已停用题目。

用户公开题目为空：

> 该用户暂未发布公开题目。

讨论区为空：

> 暂无相关讨论。

排行榜无同步数据：

> 暂无可用于排行的 OJ 数据。

### 9.3 HTTP 异常语义

- `400`：字段格式或业务参数错误；
- `401`：未登录或 Session 失效；
- `403`：已登录但无权限，或 CSRF 校验失败；
- `404`：资源不存在，或私有停用资源对当前用户不可见；
- `409`：用户名、邮箱或平台题目标识冲突；
- `500`：系统异常。

前端不能把所有 `403` 都当作未登录，也不能把所有 `404` 都显示为页面路由不存在。

## 10. 安全与隐私要求

1. 使用 Session Cookie，不在前端持久化 JWT。
2. 前端不读取或保存 `JSESSIONID`。
3. 所有写操作按后端规则携带 CSRF Token。
4. 密码不得进入日志、Store、localStorage 或错误信息。
5. 用户 ID、管理员状态和资源所有权不得由请求体决定。
6. 普通用户不能查询他人的停用题目。
7. 对他人的停用资源返回 404，避免暴露其存在。
8. 管理员页面隐藏只是前端表现，后端必须再次鉴权。
9. 数据库密码和外部平台密钥不得进入前端代码。
10. 错误响应不得暴露 SQL、索引名、堆栈和内部路径。

## 11. 非功能需求

### 11.1 性能

- 默认分页大小 20；
- 单页最大 100；
- 列表不得一次返回全文 Markdown；

- 第一版桌面端优先；
- 移动端保证基本可用；
- 手机端至少支持浏览、筛选、查看、创建和管理自己的题目；
- 表单失败后保留输入；
- 筛选条件建议同步到 URL；
- 重复停用和恢复按成功处理。

### 11.3 兼容性

目标浏览器：

- Chrome；
- Edge；
- 主流移动端浏览器。

不考虑 IE。

### 11.4 部署与运维

第一版部署到云服务器。

要求：

- 正式环境使用 HTTPS；
- 配置自定义域名；
- 需要文件存储，用于头像上传等资源；
- 第一版单实例运行，不强制使用 Redis；
- Session 暂由单实例应用管理；
- 数据库正式使用后每日自动备份；
- 备份需要保留周期和恢复演练；
- 外部 OJ 同步任务不得阻塞普通请求。

### 11.5 可维护性

- 公共列表、我的题目和管理员列表可复用基础列表组件；
- 公共响应与管理响应保持边界，不为方便前端而泄露状态；
- 权限规则在后端集中管理；
- 前端类型定义与后端 DTO 保持同步。

## 14. MVP 1 验收标准

认证：

- 用户可以注册、登录和退出；
- 刷新页面后登录状态可恢复；
- Session 失效后跳转登录；
- 写操作正确携带 CSRF。

公共题库：

- 只显示正常题目；
- 支持分页、平台、难度和关键词筛选；
- 支持按创建者查看公开题目；
- 详情字段完整。

题目创建：

- 普通用户和管理员都可以创建；
- 创建者来自当前登录用户；
- 新题默认正常；
- 重复平台题目标识返回冲突。

题目编辑：

- 创建者可以编辑自己的正常和停用题目；
- 管理员可以编辑任意题目；
- 其他用户不能编辑；
- 编辑停用题目不会自动恢复；
- 可空字段可以清空。

个人管理：

- 用户可按全部、正常、停用查看自己的题目；
- 可以停用和恢复；
- 不提供物理删除。

管理员：

- 可以查看全部正常和停用题目；
- 可以按状态和创建者筛选；
- 可以管理任意题目。

## 15. 待确认事项

当前本轮产品规则已全部确认：

- 训练计划创建后不允许在 `PERSONAL` 与 `PUBLIC` 之间切换；
- 公开计划结束后不允许新用户加入，但所有已登录用户仍可查看公开计划详情；
- Markdown 完全禁止原始 HTML；
- Codeforces 手动同步冷却时间为 1 小时。

后续只有在进入具体模块设计时，才需要继续确认字段、接口和交互细节。

## 16. 当前决策记录

已冻结的主要产品规则：

- 所有登录用户可创建题目，创建者和管理员可管理；
- 题目逻辑停用，不物理删除；
- 区分用户主动停用与管理员强制停用；
- 管理员强制停用必须填写原因，创建者可编辑但不能恢复；
- 普通用户可创建个人计划，只有管理员可创建公开计划；
- 公开计划自由加入，但用户不能主动退出；
- 公开计划不限人数，管理员可移除成员并保留历史数据；
- 训练计划创建后不允许切换个人/公开模式；
- 公开计划结束后不允许新用户加入，但仍可查看公开详情；
- 时间状态自动计算，停用状态单独控制；
- 计划结束后可以补做，但赛时排名与截止统计冻结；
- 公开计划参与者可查看成员进度；
- 做题状态仅有未做、挑战中、已通过；
- 已通过只能由可信 OJ 数据确认；
- 用户主页展示基础资料、Codeforces 账号、刷题统计、公开题目和公开计划；
- 邮箱不公开，不存学号；
- 第一版支持头像上传；
- 题目标签采用系统标签加自定义标签；
- 第一版 Markdown 图片只支持外链；
- Markdown 完全禁止原始 HTML；
- 帖子类型固定，公告仅管理员发布；
- 评论支持一级评论和一层回复；
- 帖子和评论逻辑停用；
- 第一版只支持帖子点赞；
- 第一版仅接入 Codeforces；
- 每人只能绑定一个 Codeforces 账号，同一账号不能重复绑定；
- Codeforces 账号由管理员审核；
- 支持手动同步和每日定时同步；
- Codeforces 手动同步冷却时间为 1 小时；
- 第一版不做牛客同步；
- 排行榜只统计 OJ 验证数据；
- 提供总榜、近 7 天、近 30 天；
- 用户不能隐藏或退出排行榜；
- 第一版只做站内未读通知；
- 管理员可禁用用户、提升管理员并查看操作日志；
- 禁用用户内容保留，历史排行保留但不参与当前榜；
- 首页采用社团信息与快捷入口；
- 第一版桌面端优先，移动端基本可用；
- 不做暗色模式；
- 表单草稿只保存在浏览器本地；
- 离开未保存表单需要确认；
- 管理员功能采用普通页面增强与独立入口结合；
- 使用页码分页；
- 部署到云服务器，正式环境使用 HTTPS；
- 需要文件存储；
- 第一版不使用 Redis；
- 正式使用后每日备份数据库；
- 需要数据导出；
- 前端采用 Vue 3，视觉和原型由 Stitch 阶段处理。
